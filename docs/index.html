02 / METHODFrom crash to root cause

The central question is not simply “did it crash?” It is “which invariant failed, where, and what does the evidence actually prove?”

01 — Reduce

Build the smallest deterministic reproducer and record revision, architecture, flags and execution tier.

02 — Instrument

Use ASan, debug assertions, debugger state and generated-code evidence to identify the first invalid operation.

03 — Trace the invariant

Connect the JavaScript/API input to internal representation, native code, allocation, lifetime and memory access.

04 — Classify precisely

Distinguish assertion failures, invalid frees, OOB reads/writes, type confusion and demonstrated primitives.

05 — Compare the fix

For disclosed bugs, identify the upstream defensive change and build a regression test around the broken invariant.

03 / PRINCIPLESEvidence first

Crash ≠ primitive

An ASan OOB report proves a memory-safety violation. It does not automatically prove arbitrary read/write or sandbox escape.

External ≠ bypass

External memory can be legitimate. The security question is how the address or handle was produced and validated.

Callback ≠ stable state

JavaScript callbacks can mutate observable state. Native algorithms must revalidate assumptions after reentrancy.

Ownership matters

A pointer being readable does not mean it can safely be passed to realloc/free. Lifetime and ownership are separate invariants.
